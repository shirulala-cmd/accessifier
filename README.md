# accessifier

הנגשת מסמכי PDF בעברית: מקבל PDF, מחזיר **HTML נגיש**, **PDF מתוייג (PDF/UA)** ו**דוח נגישות**.

נבנה מול ת"י 5568 (שמאמץ את WCAG 2.1 AA), תקנות שוויון זכויות לאנשים עם מוגבלות (התאמות נגישות לשירות), תשע"ג-2013, ו-ISO 14289-1 (PDF/UA).

הכלי מתקן את מה שאפשר לתקן אוטומטית ומדווח על כל השאר. הוא לא ממציא תיאור חלופי לתמונה, והוא לא קובע שמסמך "עומד בתקן" — זו קביעה אנושית שדורשת מעבר אמיתי עם קורא מסך.

## התקנה

```bash
pip install -r requirements.txt
```

יש גם תלויות שאינן חבילות פייתון. בלעדיהן חלק מהפונקציונליות נופלת בשקט, ולכן כדאי להתקין את כולן:

```bash
# Debian / Ubuntu
sudo apt install tesseract-ocr tesseract-ocr-heb ghostscript \
                 libpango-1.0-0 libpangoft2-1.0-0 libcairo2 libgdk-pixbuf-2.0-0

# macOS
brew install tesseract tesseract-lang ghostscript pango cairo gdk-pixbuf
```

חבילת העברית של Tesseract (`tesseract-ocr-heb`) היא לא אופציונלית: בלעדיה OCR על מסמך סרוק יחזיר ג'יבריש ולא עברית.

## שימוש

הדרך הקצרה — תיקייה שלמה בפקודה אחת:

```bash
python הנגש.py
```

בריצה הראשונה נוצרת תיקייה בשם `מסמכים`. שימי בה קובצי PDF, הריצי שוב, והפלט ייכתב ל`פלט` — קובץ אחד או מאה, לא משנה. בסוף הריצה מודפס סיכום של מה יצא ואילו קבצים דורשים בדיקה ידנית. אפשר גם לתת תיקייה או קובץ מסוים:

```bash
python הנגש.py ~/Downloads
python הנגש.py קובץ.pdf
```

הדרך המפורשת, לקובץ אחד עם שליטה על הדגלים:

```bash
python -m accessifier מסמך.pdf -o out/
```

נוצרים שלושה קבצים ב-`out/`:

| קובץ | מה הוא |
|---|---|
| `<שם>-accessible.html` | HTML נגיש, RTL, עם קישור דילוג ותוכן עניינים. זו בדרך כלל החוויה הטובה ביותר ב-NVDA |
| `<שם>-accessible.pdf` | PDF מתוייג עם עץ תיוג, שפה וכותרת מסמך |
| `<שם>-accessibility-report.html` | דוח: מה אובחן, מה תוקן ומה דורש טיפול ידני |

### דגלים

```
--force-level {A,B,C}   כפיית רמת טיפול במקום האבחון האוטומטי
--diagnose-only         אבחון בלבד, בלי ליצור פלט
--skip-ocr              לא להריץ OCR גם אם זוהו עמודים סרוקים
--skip-pdf              HTML ודוח בלבד
--verapdf               להריץ VeraPDF אם הוא מותקן
--json                  פלט בפורמט JSON (נקי, מתאים לצינור או לשרת)
-q / -v                 שגיאות בלבד / לוג מפורט
```

### מתוך פייתון

```python
from accessifier import process

result = process("מסמך.pdf", "out/")
print(result.level)                    # Level.A / Level.B / Level.C
print(result.manual_review_required)   # True כשיש פריט שלא תוקן אוטומטית
print(result.html_path, result.pdf_path, result.report_path)
```

## שלוש רמות טיפול

האבחון מחליט כמה אגרסיבי הטיפול צריך להיות. ההיגיון: לא לשנות עיצוב שאין צורך לשנות, אבל גם לא להתעקש לשמר עיצוב שאי אפשר להנגיש בתוכו.

* **רמה A — תיוג בלבד.** המסמך תקין: הטקסט חולץ נכון, המבנה ברור. העיצוב נשמר.
* **רמה B — שחזור מבנה.** הכותרות, הרשימות והטבלאות לא מסומנות ויש לשחזר אותן. העיצוב נשמר בעיקרו.
* **רמה C — בנייה מחדש עם עיצוב נגיש.** המסמך פגום מכדי להנגיש אותו במקום — למשל עברית בקידוד מיושן, או ניגודיות שלא עומדת בתקן. התוכן נבנה מחדש בעיצוב נגיש.

## עברית בקידוד מיושן — החלק שבאמת שובר מסמכים

הרבה PDF-ים ישראליים ישנים מטמיעים גופנים שמיפוי ה-ToUnicode שלהם מצביע על **Windows-1255** ולא על העברית של Unicode. הטקסט שמחולץ מהם נראה כמו אותיות לטיניות עם סימנים: `äñéìåôä` הוא בעצם `הפוליסה`. אותם קבצים גם שומרים כל שורה ב**סדר חזותי** (הפוך), ולפעמים אפילו כל מילה כנתח נפרד.

הכלי מזהה את זה, מפענח מחדש ומשחזר את סדר הקריאה. שתי החלטות מהותיות בדרך:

**הקידוד נקבע פעם אחת לכל המסמך, לא שורה-שורה.** הקידוד הוא תכונה של הקובץ. ניחוש פר-שורה מייצר תערובת של טקסט מתוקן ולא מתוקן, וזה גרוע משתי האפשרויות.

**מספרים, תאריכים, סכומים וכתובות אינטרנט לא מתהפכים.** הם נשמרים בסדר קריאה גם בתוך שורה הפוכה, ולכן היפוך שלהם משנה את המשמעות בשקט. מיקוד או תאריך פירעון שהתהפכו גרועים בהרבה ממסמך שלא תוקן בכלל.

## מה הכלי לא יעשה

* **לא ימציא תיאור חלופי לתמונה.** כשאין טקסט שאפשר להסתמך עליו, התמונה מקבלת תיאור מפורש שאומר שדרוש תיאור, והפריט נכנס לדוח כ"דורש טיפול ידני". `alt` ריק היה הופך את התמונה לדקורטיבית ומסתיר את עצם קיומה.
* **לא יקבע שהמסמך עומד בתקן.** הכלי מדווח מה נבדק ומה תוקן. אישור נגישות דורש בדיקה אנושית עם קורא מסך.

## בדיקות

```bash
python -m pytest tests/ -q
```

הבדיקות בונות קבצי PDF בעברית בזמן ריצה (כולל מסמך בניגודיות נמוכה ומסמך "סרוק" בלי שכבת טקסט), מסירות מהם את עץ התיוג כדי שיֵדמו למסמכים אמיתיים, ואז מריצות עליהם את כל הצינור.

## מבנה

```
הנגש.py          הרצה על תיקייה שלמה. נוחות בלבד, עוטף את pipeline
accessifier/
  triage.py      אבחון: קביעת רמה A/B/C
  ocr.py         OCR לעמודים סרוקים
  rtl.py         עברית: קידוד, סדר תווים, ניקוי
  structure.py   חילוץ מבנה: כותרות, רשימות, טבלאות, תמונות
  to_html.py     רינדור HTML נגיש
  tag_pdf.py     יצירת PDF מתוייג מה-HTML
  validate.py    בדיקות מבנה על הפלט
  report.py      דוח הנגישות
  pipeline.py    תזמור: כל שלב יכול להיכשל בלי להפיל את השאר
```

ה-PDF המתוייג נוצר **מה-HTML הנגיש** ולא על ידי תיקון הזרם המקורי. זה אומר שסמנטיקה אחת מזינה את שני הפלטים, ושאיכות ה-HTML היא איכות ה-PDF.
